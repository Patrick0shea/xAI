## What was discussed / decided

Set up the group's journal repository ahead of the group forming/meeting properly, so the record-keeping requirement is in place from day one rather than retrofitted later.

Decisions made:

- Using the simple `journal/` folder convention (one dated Markdown file per entry) rather than GitHub Issues/Projects, since we're a small group and flat files are easier for everyone to commit to directly without needing to learn the Issues workflow.
- Added a `journal/TEMPLATE.md` so entries have a consistent shape (what/why/open/who-did-what) and nobody has to guess the expected format.
- `README.md` is set up as the living pointer to topic, scope, team members, and the latest report draft — to be filled in once the topic is confirmed.

## Why

Regularity and traceability are graded from commit history, so the repo needed to exist and be usable before substantive work started, not bolted on the week before submission. A flat-file journal keeps the barrier to committing low, which matters for getting genuinely distributed authorship across the group rather than one person transcribing for everyone.
