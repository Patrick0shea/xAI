## Why

- **Why trace the crash instead of switching to a GPU straight away:** the speed test
  showed the VM was fast enough. The run was failing, not slow, so a fix was worth finding.
- **Why record the run details:** this run differs from the baseline in ways a reader
  needs to know.
  - **Hardware and precision:** it ran on a CPU in 32-bit floats; the baseline ran on a
    GPU in 16-bit.
  - **Kernel setting:** it needed `ATEN_CPU_CAPABILITY=default`. That only changes which
    version of PyTorch's internal kernels runs, not the method, but the same seeds may
    still produce different random draws than on a GPU.
  - **Model version:** the script logged `model_revision: null`, so I checked the
    downloaded version by hand: `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`. That matches
    the version pinned in Fionn's notebook.

  Fionn's protocol already treats the hardware difference as a confound; these details
  should be stated in Section III-E.
